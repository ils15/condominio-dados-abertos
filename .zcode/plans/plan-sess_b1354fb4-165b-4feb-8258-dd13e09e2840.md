# Portal de Dados Abertos do Condomínio — v1 (React + Vite)

## Contexto
Sistema de dados abertos do condomínio pra síndica: documentos de manutenção (hidráulica, elétrica, mecânica, estrutural, serviços) + cronograma com o que é, quando foi feito e valor estimado (baseado na última manutenção). Decisões ajustadas com o usuário: **visual de dashboard moderno** (o sóbrio foi rejeitado), **React** (não Electron — este seria app desktop de ~150MB, incompatível com github.io), **CSV como fonte** com **export SQLite** (síndica edita em planilha/web do GitHub; quem quiser SQL baixa o .sqlite). Hospedagem: github.io agora (GitHub Action rebuilda a cada mudança de CSV), domínio próprio do condomínio depois — mesmo artifact estático.

## Stack
- **Vite + React 19 + Tailwind 4 + Recharts + lucide-react** — compila pra estático, zero backend.
- **vite-plugin-singlefile** com `assetsInlineLimit` alto: build vira **um `index.html` autocontido** → cópia local = dois cliques, abre offline em qualquer navegador (inclusive via `file://`, sem problema de CORS de módulos).
- Dados carregados em runtime via `<script src="./data.js">` clássico (funciona em `file://`): dá pra regenerar os dados com só Python, sem rebuild do app.
- Roteamento com HashRouter (`#/cronograma`) — refresh funciona no gh-pages subpath e offline.
- Sem CDN/fonte externa — 100% offline. Fonte: stack do sistema.

## Estrutura
```
condominio/
├── dados/                  # FONTE DA VERDADE (síndica edita; UTF-8, ";", auto-detect)
│   ├── ativos.csv  cronograma.csv  manutencoes.csv  prestadores.csv
├── documentos/<categoria>/*.pdf
├── scripts/gerar_dados.py  # stdlib: valida CSVs (erros em PT-BR), calcula derivados,
│                           # escreve public/data.js + cópias CSV/JSON + condominio.sqlite + datapackage.json
├── src/                    # app React (páginas, componentes, tema)
├── public/                 # gerado/copiado pelo script (data.js, dados/, documentos/)
├── .github/workflows/deploy.yml  # push → gerar + build → gh-pages
├── LEIAME.md               # guia da síndica (editar CSV no GitHub web, gerar, publicar, LGPD)
└── dist/                   # build publicável = cópia local
```

## Lógica de manutenção (igual ao plano anterior, mantida)
Próxima execução = última vinculada + periodicidade; valor estimado = média das execuções (senão `valor_referencia`); status atrasado/vence≤60d/em dia; agregações por categoria e mês; estimativa anual do plano.

## Visual — Dashboard claro (shadcn/Vercel-like) + dark mode
- Sidebar com navegação, header com busca global e toggle de tema (persiste em localStorage).
- **Painel**: cards (gasto no ano, manutenções executadas, atrasadas), donut de gastos por categoria (Recharts), barras por mês, lista "próximas" com badges de status e valor estimado.
- **Cronograma**: tabela com filtros (categoria/status/tipo), próxima data, periodicidade, estimativa, total anual estimado.
- **Histórico**: lançamentos com filtros e soma; link pro documento (PDF) de cada execução.
- **Prestadores** e **Documentos** (navegação por categoria, links relativos).
- **Dados Abertos**: catálogo estilo CKAN — metadados, downloads CSV/JSON/**SQLite**, `datapackage.json`, licença (CC BY 4.0 sugerida).
- Responsivo (morador no celular), PT-BR, badges coloridos, tipografia Inter-stack.

## Dados de exemplo
Fictícios e marcados (Edifício Exemplo): elevador, bombas/caixa d'água, quadro elétrico, laje/fachada, limpeza/jardinagem; histórico 2023–2026 com valores variados (demonstra estimativa e itens atrasados); 4 PDFs mínimos válidos gerados pelo script.

## Fora do escopo v1
Login (LEIAME documenta opções pro cenário moradores-only), domínio próprio (basta apontar CNAME), app desktop.

## Verificação
1. `python3 scripts/gerar_dados.py` valida os CSVs exemplo sem erros e gera `public/data.js`, `sqlite` e datapackage.
2. `npm install && npm run build` limpo → `dist/` com index.html único + data.js + dados/ + documentos/.
3. `python3 -m http.server` em dist + navegação com browser-use (screenshots): tabs, filtros, donut, badges, busca.
4. Abrir `dist/index.html` direto via `file://` no navegador → mesma experiência (prova da cópia local offline).
5. Spot-check numérico: estimativa = média dos lançamentos vinculados; item vencido aparece "atrasado".
6. Ao final: `git init` + commit inicial só se você quiser (não faço sem confirmar).
